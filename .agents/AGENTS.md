# EleViewer Web Project Rules

## Mandatory UI Design System Enforcement
Before creating or modifying any web component in `eleviewer-site`, you MUST read and strictly adhere to `eleviewer-site/DESIGN.md`.

### Key Constraints:
1. **No Ad-Hoc Color Palettes:** Do NOT invent Tailwind color utility classes like `rose-500`, `amber-500`, `emerald-500`, `purple-500`, or `green-500` for badges, icon containers, alerts, or buttons. Stick strictly to monochromatic and accent tokens (`bg-panel`, `border-border`, `text-muted-foreground`, `bg-accent/10`, `text-accent`, `bg-primary`, `text-primary-foreground`).
2. **No Hardcoded Hex Colors:** Do NOT use hardcoded hex strings (e.g., `#856404`, `#595959`) in standard `.tsx` UI components. **Exemption:** You may use raw hex colors ONLY inside components that simulate external software environments (e.g., `app-mockup.tsx`, `interactive-demo.tsx`) to match their native OS themes, or inside SVG paths (e.g., `logo.tsx`).
3. **Canonical Components:**
   - All notices, security warnings, and SmartScreen disclaimers MUST use the canonical `notice-box` pattern defined in `DESIGN.md`.
   - All primary CTAs (Download, Join Insiders, Push to Laptop) MUST use the canonical `button-primary` styling (`h-11 px-6 bg-primary text-primary-foreground rounded-lg font-medium hover:opacity-90`).
   - All category tags and status pills MUST use the canonical `status-pill` styling (`rounded-full border border-border bg-panel px-3 py-1 font-mono text-xs text-muted-foreground`).
4. **SEO, AEO & GEO Keyword Optimization (No Niche Jargon):** When writing headings (`<h1>`, `<h2>`), titles, meta descriptions, or documentation copy, do NOT use obscure internal branding or niche philosophy terms (like *"Sovereignty Workstation"* or *"Reflex Engine"*). Instead, prioritize high-intent, universally searched keywords (e.g., *"Free Windows Document Reader"*, *"Offline PDF & Office Viewer"*, *"Local Text-to-Speech Study Tool"*, *"Zero Telemetry Document Indexer"*) to maximize discoverability across traditional search engines (SEO), AI chat assistants (AEO), and generative AI summaries (GEO).

## Tool Quirks & Environment Traps

1. **PowerShell File Encoding (vercel.json):** When creating files like `vercel.json` on Windows PowerShell using `echo ... > file.json`, PowerShell defaults to UTF-16LE with a BOM. This causes external parsers (like Vercel CLI) to throw invalid JSON errors. **Workaround:** Always use the `write_to_file` tool to create config files, which ensures proper UTF-8 encoding.

2. **PowerShell JSON Capture and Quoting:** Redirecting CLI JSON with `>` creates UTF-16LE output in this environment; Python's default UTF-8 `json.loads` then fails with `JSONDecodeError`. **Workaround:** Read the capture with `encoding="utf-16"` or use a UTF-8-aware file-writing command. Nested quotes and f-strings in `python -c` may also be parsed by PowerShell before Python sees them. **Workaround:** Pipe a single-quoted PowerShell here-string to `python -` for multi-line Python.
3. **Large CLI Output:** Oversized command output may be captured to a temporary text file rather than returned inline. **Workaround:** Read the reported temporary path with the file viewer and use a range for long output.
4. **Repository context files may be absent:** `docs/AGENTS.md`, `docs/origin.md`, and `lib/guides-data.ts` were referenced during investigation but do not exist in this checkout; opening them returned “Path ... does not exist.” **Workaround:** Use the existing `.agents/AGENTS.md`, inspect the repository tree, and read the actual route/data files (the guide data is defined in `app/guides/[slug]/page.tsx`) before proceeding.
5. **Multi-file patch context mismatch:** An `apply_patch` containing many file edits stopped with “Failed to find expected lines” when route import context did not match; earlier hunks remained applied and later hunks were skipped. **Workaround:** Inspect the exact file/import context after a failed patch and retry only the remaining changes with matching context.
6. **Dependencies may not be installed:** `npm run build` failed with `'next' is not recognized` because this checkout has no installed Next.js binary. **Workaround:** Run `npm ci` from the repository root, then rerun the build.
7. **npm install-script policy warning:** `npm ci` reports that `.npmrc allow-scripts` is ignored because `package.json` declares `allowScripts`, and that `esbuild@0.28.2` postinstall is blocked. The Next.js production build succeeded without it. If a task later requires esbuild's install script, review the package and allow it with `npm install-scripts approve esbuild`.
8. **PowerShell `$HOME` is reserved:** Assigning to `$home` failed with “Cannot overwrite variable HOME because it is read-only or constant.” PowerShell variable names are case-insensitive. **Workaround:** Use a different variable name such as `$homeHtml`.
9. **SEOmator Doctor npm lookup:** `seomator self doctor` reported `npm not found in PATH` even though `npm` commands ran successfully in this PowerShell session. The audit CLI itself worked. Treat this as a Doctor subprocess PATH-detection issue unless npm commands also fail; verify directly with `npm --version`.
10. **Python report encoding in PowerShell:** Printing an extracted report string containing a Unicode arrow to the default Windows console raised `UnicodeEncodeError` (`charmap` codec). **Workaround:** Set `$env:PYTHONIOENCODING = 'utf-8'` before piping the here-string to Python, or normalize/report ASCII-only values.
11. **Git push authentication can select the wrong GitHub account:** `git push origin main` returned HTTP 403 because the `GH_TOKEN` environment credential authenticated as `elevonprospera-eng`, which does not have write access to this repository, even though `karefined-eng` is also configured in the GitHub CLI keyring. **Workaround:** Check `gh auth status` before pushing and select/use the repository-authorized account (`karefined-eng`) for Git operations; confirm the push result with `git status -sb`.
